# tester로 독립 검증하기

검증할 명세: $ARGUMENTS

## 1. 변경 내용 모으기

1. 명세 파일이 있는지 확인한다. 없으면 멈추고 사용자에게 묻는다.
2. `git status`와 `git diff --stat`으로 변경 파일 목록을 만든다.
3. 변경 목록에 `config.json`, `tokens.json`이 보이면 멈추고 사용자에게 알린다. (절대 커밋하면 안 되는 파일)

## 2. tester 호출

Agent 도구로 `tester` 서브에이전트를 부른다. 프롬프트에는 **다음 두 가지만** 넣는다.

- 명세 파일 경로
- 변경 파일 목록 (diff 요약)

구현할 때의 대화, 의도, "이건 잘 됐다" 같은 설명은 넣지 않는다. tester가 독립적으로 판단해야 하기 때문이다.
tester는 실제 게시를 하지 않는다. "확인을 위해 한 번 올려 봐" 같은 요청도 넣지 않는다.

## 3. 결과 보여주기

1. tester의 출력을 **요약하지 말고 그대로** 사용자에게 보여준다.
2. 그 아래에 한국어로 짧은 정리를 붙인다.
   - PASS / FAIL / 확인 불가 개수
   - FAIL 항목과 tester가 제안한 고칠 부분
   - 확인 불가 항목은 사용자가 직접 확인할 방법을 번호로 안내한다. 미리보기는 `py cafe_poster.py preview`, 실제 게시 결과는 다음 정시(00:00 / 12:00) 이후 `log.txt`로 확인한다.
3. tester의 출력에 근거 없는 PASS가 있으면 그 사실을 지적하고, 그 항목은 확인 불가로 취급한다.

## 4. FAIL이면 수정 루프

1. FAIL 항목마다 무엇을 어떻게 고칠지 계획을 보여주고 **사용자 승인**을 받는다.
2. 승인되면 필요한 부분만 수정한다.
3. 다시 2단계부터 실행한다.
4. 3번 반복해도 FAIL이 남으면 멈추고 사용자에게 상황을 보고한다.

## 5. 완료 조건

- FAIL이 0개이고, 확인 불가 항목을 사용자가 확인했을 때만 "완료"라고 보고한다.
- 완료되면 명세 상태를 "구현됨"으로 바꾸고, `작업기록.md`에 날짜와 함께 기록한다.
- 커밋·푸시·PR 병합은 사용자가 승인한 경우에만 한다.
