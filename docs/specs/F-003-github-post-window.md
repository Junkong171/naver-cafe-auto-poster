# F-003: GitHub 게시 시간 제한 + 예약 횟수 늘리기

- 상태: 구현됨 (2026-11-26, tester PASS 9 / FAIL 0, AC-10은 병합 뒤 확인)
- 작성일: 2026-11-25
- 관련 파일: `cafe_poster.py`, `.github/workflows/post.yml`, `README.md`, `config.example.json`

> 이 파일은 GitHub 공개 저장소에 올라갑니다. Client ID/Secret, 토큰, 개인 정보, 실제 카페·게시판 ID는 쓰지 않습니다.

## 목적

F-002로 GitHub Actions 게시를 켰지만, 첫날(11/24) GitHub 예약 실행은 4번 중 1번만 돌았고 그것도 54분 늦었다. 그래서 두 글을 모두 PC가 정시 + 90분 뒤에 보충했다. 22:31에는 PC 게시와 늦게 시작된 GitHub 실행이 56초 차이로 겹쳤다. 게시판 중복 확인이 막았지만, 몇 초 차이였다면 중복 게시가 될 수 있었다.

두 가지를 고친다.
1. GitHub이 게시할 수 있는 시간을 정시 + 80분까지로 제한한다. 그 뒤는 PC 몫(정시 + 90분부터)이라, 두 곳이 같은 순간에 올릴 수 없게 된다.
2. 예약 실행을 시간대마다 2번에서 6번으로 늘린다. 몇 번 빠지거나 늦어도 GitHub이 정시 근처에 올릴 가능성을 높인다.

## 확인한 사실 (출처)

- 11/24 Actions 기록(`gh run list`): schedule 실행은 1번뿐. UTC 13:31:50 시작(= 한국 22:31, 21:37 예정분이 54분 늦음). 로그: "게시판에 11/24 21:00 글이 이미 있어서 건너뜀" (22:31:59)
- PC `log.txt`: 11/24 13:31:03, 22:31:03 PC 보충 게시, 둘 다 "정상적으로 1개 올라감"
- GitHub 문서 "Events that trigger workflows > schedule": 부하가 높을 때 예약 실행이 늦어지거나 빠질 수 있음, 정각이 특히 붐빔 (F-002에서 확인)
- 액션 버전 (`gh api repos/actions/.../releases/latest`, 2026-11-25): `actions/checkout` 최신 v7.0.1, `actions/setup-python` 최신 v7.1.0. 둘 다 `action.yml`이 `using: node24` → 지금 쓰는 v4/v5의 "Node.js 20 is deprecated" 경고가 사라짐
- 11/25 결과: 12시대 GitHub 실행 0번(PC가 15:13에 보충), 21시대는 21:36에 GitHub이 **직접 게시 성공**(대표사진 thumb_a, "정상적으로 1개 올라감") → 해외 IP에서도 카페 글쓰기가 됨. PC는 22:31에 "이미 있어서 건너뜀"
- 공개 저장소의 표준 러너는 무료 (F-002). 한 번 실행에 약 15초, 하루 12번이면 약 3분

## 동작 시나리오

1. 워크플로가 한국 시각 12:05, 12:20, 12:35, 12:50, 13:05, 13:15 (21시대도 21:05 ~ 22:15)에 실행된다. 마지막은 마감(정시 + 80분)보다 앞서야 올릴 수 있어서 :15 (tester 지적 반영)
   - cron(UTC): `5,20,35,50 3,12 * * *` 와 `5,15 4,13 * * *`
2. GitHub 실행의 설정에 `"post_window_minutes": 80`이 들어간다.
3. `run`은 "가장 최근 정시 + 80분"이 지났으면 게시 검토를 하지 않고 "PC 보충 시간이라 GitHub은 올리지 않음"을 출력하고 끝낸다. 실패가 아니라 정상 종료다 (메일 안 옴).
4. 80분 안이면 지금처럼 게시판 중복 확인 → 3시간 간격 → 사진 확인 → 게시 → 게시 후 확인을 거친다. 먼저 올린 실행 뒤의 실행은 "게시판에 … 이미 있어서 건너뜀"으로 끝난다.
5. PC는 그대로 `backup_delay_minutes` 90이다. 정시 + 90분 뒤에도 게시판에 글이 없을 때만 올린다.
6. `post_window_minutes`가 없으면 (PC 포함) 지금과 똑같이 동작한다.

```
정시 ─── GitHub 게시 가능 (0~80분) ───┤ 10분 비움 ├─── PC 보충 가능 (90분~) ───
```

## 게시 영향

| 항목 | 내용 |
|---|---|
